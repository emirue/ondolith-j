# Phase 0 구현 계획 — 설치, 뼈대, CI, 보안 기본값

> **에이전트 작업자에게:** 필수 하위 스킬 — `superpowers:subagent-driven-development`(권장) 또는 `superpowers:executing-plans` 로 작업 단위로 실행한다. 단계는 체크박스(`- [ ]`)로 추적한다.

**목표:** 빈 DB 와 jar·프런트로 시작해 브라우저에서 설치 폼을 내면 대기 화면을 거쳐 홈에 사이트 이름이 보이고, 이 흐름을 Playwright 와 CI 가 자동으로 검증한다.

**구조:** 한 JVM 안에 Spring 컨텍스트가 둘이다. `Launcher` 가 설정 파일을 보고 설치 컨텍스트(DB 없음) 또는 운영 컨텍스트(DB·JPA·Flyway)를 띄우고, 설치가 끝나면 설치 컨텍스트를 닫고 같은 포트로 운영 컨텍스트를 띄운다. 프런트는 Vite 로 빌드한 React SPA 이고 `/api/health` 로 화면을 고른다.

**기술:** Java 25, Spring Boot 4.1.2(Maven), Spring Security 7.1, Spring Data JPA, Flyway, PostgreSQL 18, Testcontainers / React 19, Vite 8, TypeScript 7, Tailwind 4, shadcn/ui, React Router, TanStack Query, React Hook Form + Zod, openapi-typescript·openapi-fetch, Vitest, Playwright.

**스펙:** `docs/superpowers/specs/2026-11-11-phase0-design.md` (결정 근거 `docs/decisions.md`). 실행자는 스펙과 이 계획을 함께 읽는다.

## 전역 제약

- 저장소는 PUBLIC. 실제 이메일·홈 절대 경로·토큰·비밀번호·생성 비밀번호를 커밋하지 않는다. 커밋 전 `scripts/check-public.sh`(훅이 자동 실행). 시험 값은 누가 봐도 가짜(`admin@ondolith.test`, `correct-horse-battery`).
- 판: 스펙 1절 표 그대로. 표에 없는 의존성을 넣지 않는다(Zustand 는 UI 상태가 처음 생길 때 넣는다 — Phase 0 에는 없다). 추가 전 OSV 확인. `pom.xml` 에 판 범위 표기 금지.
- API·라이브러리 사용법은 기억으로 쓰지 않고 context7(모자라면 공식 문서)로 확인한다. 특히 Boot 4 의 자동 구성 클래스 이름은 3.x 와 패키지가 다르다.
- 모든 사용자 대상 문구·커밋 메시지는 한국어. 커밋 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- CPU·메모리: 무거운 작업(빌드·Testcontainers·Playwright·측정)은 한 번에 하나, 호스트 명령은 `nice -n 19`. 개발 서버·브라우저는 쓰고 끈다.
- TDD: 시험을 먼저 쓰고 **옳은 이유로 실패**하는 것을 본 뒤 구현한다. skip·삭제·단언 완화 금지.
- 측정 앱(`bench/`)의 코드·의존성·설정은 바꾸지 않는다(경로 이동만).
- JSON 필드 이름은 snake_case(`spring.jackson.property-naming-strategy=SNAKE_CASE`, 두 컨텍스트 공통). ondolith D19 의 필드 이름과 같다.
- 설치 API 의 HTTP 상태: 검증 422 / 설정 파일 자리 못 씀 500 / DB 접속 실패·사용 중 DB·마이그레이션 실패 400 / 동시 요청 409 / 설치 끝난 뒤 404 / 성공 202.

## 검토 초점

스펙이 함의하지만 기능 시험만으로는 놓치기 쉬운 것. 각 줄의 시험은 담당 작업에 넣었다.

1. **로그에 비밀이 남음** — Spring Security 의 생성 비밀번호, 설치 요청의 `db_password`·`admin_password`, JDBC URL. 기대: 어느 로그에도 없다. → 작업 5·7 (`UserDetailsServiceAutoConfiguration` 제외 + 로그 캡처 시험).
2. **DB 접속 오류 원문에 비밀번호가 섞임** — 드라이버 메시지가 입력값을 되풀이하는 경우. 기대: 응답 본문에 `db_password` 값이 없다. → 작업 7 (메시지에서 비밀번호 문자열을 지우는 처리 + 시험).
3. **설치 중 실패 후 재시도** — 마이그레이션은 됐는데 관리자 생성 전에 실패, 또는 설정 파일 쓰기 실패. 기대: 같은 입력으로 다시 내면 설치가 끝난다(「이미 계정이 있음」에 막히지 않는다). → 작업 7 (재시도 시험).
4. **첫 POST 에 CSRF 토큰 쿠키가 없음** — `csrf.spa()` 의 지연 로딩 때문에 첫 GET 이 쿠키를 주지 않을 수 있다. 기대: 프런트가 `/api/health` 한 번 부른 뒤의 첫 POST 가 403 이 아니다. → 작업 5 (GET 응답에 `XSRF-TOKEN` 쿠키 단언) · 작업 13(E2E 가 실제로 증명).
5. **전환 직후 포트가 아직 안 풀림** — 설치 컨텍스트의 Tomcat 이 내려가기 전에 운영 컨텍스트가 같은 포트를 잡으려 함. 기대: 운영 컨텍스트가 뜬다. → 작업 8 (같은 JVM 전환 시험) · 작업 13(실제 jar).

### 작업 4: 기동 분기와 두 컨텍스트, 헬스

**파일:**
- 만들기: `Launcher.java`, `RunningApplication.java`, `install/InstallApplication.java`, `shared/AppState.java`, `shared/HealthController.java`, `src/main/resources/application.properties`
- 시험: `LauncherTest.java`, `shared/HealthControllerTest.java`

**인터페이스(만든다):**
- `Launcher.main(String[] args)` — `--config=<경로>`(기본 `./ondolith-j.properties`)를 읽고 `ConfigFile.load` 결과로 분기. `Broken` 이면 `System.err` 에 `설정 파일이 잘못됐습니다: <경로>: <reason>` 한 줄, exit 1(FR-110).
- `static int Launcher.run(String[] args)` — 패키지 내부. 분기·기동을 하고 종료 코드(정상 기동 0, 깨진 설정 1)를 돌려준다. `main` 은 0 이 아니면 `exitHandler` 로 넘긴다.
- `static IntConsumer Launcher.exitHandler = System::exit` — 패키지 내부. 시험이 바꿔 끼운다(작업 8).
- `static ConfigurableApplicationContext Launcher.startInstall(Path configFile, String... args)` / `startRunning(ConfigFile config, String... args)` — 시험과 전환이 쓴다. `startRunning` 은 `spring.datasource.url/username/password` 를 `SpringApplicationBuilder.properties(...)` 로 넘긴다(환경변수·파일로 새지 않게).
- `InstallApplication`: `@SpringBootConfiguration @EnableAutoConfiguration(exclude = DataSource·JDBC·JPA·Flyway·UserDetailsService 자동 구성)` + `@ComponentScan("dev.ondolithj.install")` + `@Import({SecurityConfig.class, ApiErrors.class, HealthController.class})` + `@Bean AppState appState() { return new AppState("install"); }`. 제외할 클래스 이름은 context7 로 Boot 4.1 기준 확인.
- `RunningApplication`: 루트 패키지 스캔에서 `dev.ondolithj.install` 제외, `UserDetailsService` 자동 구성 제외, `@Bean AppState("running")`.
- `GET /api/health` → `200 {"state": "install"|"running", "version": "<BuildProperties.version>"}`

- [ ] **1단계: 실패하는 시험**
  - `HealthControllerTest`(`@WebMvcTest` 대신 `Launcher.startInstall(tempDir 의 없는 설정, "--server.port=0")` 로 실제 설치 컨텍스트 + `RestTestClient`): `state` 가 `install`, `version` 이 비어 있지 않음.
  - `LauncherTest`: 깨진 설정 파일로 `Launcher.run(args)`(exit 대신 종료 코드를 돌려주는 패키지 내부 메서드) → `1`, `System.err` 캡처에 설정 파일 경로와 문제 키.
  - `LauncherTest.설치_컨텍스트에는_DataSource_빈이_없다`: `startInstall(...).getBeanNamesForType(DataSource.class)` 비어 있음.
- [ ] **2단계: 실패 확인** — `./mvnw -q -B test -Dtest='LauncherTest,HealthControllerTest'` → 컴파일 실패.
